# 备份、导出与迁移

[返回 README](../README.md)

## 备份文件（导出 / 导入）

侧栏「导入」菜单 →「导出全部连接…」/「导入 LiteShell 备份…」，一个 JSON 文件装下：文件夹树、连接、
私钥库、模型配置（接口 + 模型名）、界面设置（主题 / 字体 / 面板宽度）、已信任的主机指纹。
主机指纹跟着走是为了省掉在每台服务器上再点一次「信任」——所以这个文件要和里面的私钥一样对待，
别乱传。

**口令是可选的，但它决定对面要不要重新输密码**：

| 导出时 | 文件里有什么 | 另一台机器导入后 |
| --- | --- | --- |
| 设了口令 | 密码、私钥口令、API Key 用 scrypt(32 MB) + AES-256-GCM 加密后放进 `secrets` | 输一次这个口令，密码就存进本机钥匙串，**连接不用再输任何东西** |
| 留空 | 只有连接、私钥、模型接口和模型名 | 密码/API Key 留在这台机器上（钥匙串密文跨机器解不开），首次连接让你补录 |

界面设置和主机指纹两样**不走口令**（它们不是秘密）：导入就换过去，连服务器时不再逐台确认。

私钥（PEM 字节）**永远是明文**在文件里，和 FinalShell 的 `config.json` 一样——文件按 0600 写，
传出去得自己负责。口令错了或者文件被改过，GCM 校验会直接拒绝，导入报错而不是半途写进去；
导出时口令要输两遍，因为打错这件事只有在另一台机器上才会发现。

### 单条导出

连接列表右键 →「导出」，只带这一条连接和它用到的私钥。导入口令规则与整份备份相同：
设了口令就把这条连接自己的密码和私钥口令一起加密带走，不设就只带走连接本身。

## 从 FinalShell 迁移

侧栏「导入」→ 选目录。两种目录都认：

| 你手里的东西 | 结构 |
| --- | --- |
| 安装目录 | `<安装目录>/conn/`，每个文件夹一个目录带 `folder.json` |
| **右键 → 导出得到的目录** | 一堆 `*_connect_config.json` 按目录分好，**没有 `folder.json`** |

导入器同时兼容这两种：有 `folder.json` 就用它拿文件夹名和 `parent_id`；没有就把目录路径本身当作
文件夹层级（目录名 = 文件夹名）。导出树里的 `parent_id` 指向源机器的文件夹 id，已经无效，会被忽略。

其余行为：

- 只搬 `conection_type: 100`（SSH），其它传输方式跳过
- id 加 `fs-` 前缀，重复导入是覆盖而不是堆叠
- `config.json` 的 `secret_key_list[].key_data` 是 **base64 的明文 PEM 私钥**，会被解出来写到
  `<用户数据目录>/keys/<id>.pem`（0600），连接自动指过去，并顺带登记进**私钥库**供其它连接复用
- **密码搬不过来**：FinalShell 用运行时拼出来的密钥加密（Blowfish/DES 家族），没有硬编码字面量。
  密码认证的连接照常导入但密码留空 —— **点连接时会弹框让你补录**，勾选「保存到系统钥匙串」
  则连接成功后才写入（避免打错的密码被存下来）

在真实数据上跑过：安装目录 20 条连接 / 4 个文件夹，恢复 1 个私钥，4 条连接引用的私钥已不在
`config.json` 里（FinalShell 侧删过），会给出告警并留空；导出的目录树 50 条连接 / 11 个文件夹。

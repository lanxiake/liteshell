# LiteShell 深空指挥台 UI · 设计规格

日期：2026-11-08  
状态：待用户审阅  
范围：焦点面仪式感增强（方案 B）+ CLI/技能包同步验收

## 1. 背景与目标

LiteShell 是 Electron + xterm.js 的 SSH/SFTP 客户端，已有深色壳层、粒子背景、AI 面板与 CLI 轨迹（`cli-trace`）。用户希望界面更有科技感、机械感与高级感，并验证「通过内置技能/CLI 操作服务器时，页面是否同步显示命令与动作」。

成功标准：

1. 连接建立、AI/CLI 命令反馈具备短而准的「科幻机械」仪式感。
2. 标题栏/侧栏/标签/状态栏/弹层有统一的咬合反馈，但不重做信息架构。
3. 多主题保留；默认深色拉满指挥台语言，其它主题跟随 CSS 变量。
4. CLI `exec` 等操作在 AI 面板实时出现意图与任务卡；验收可复现。

## 2. 决策摘要

| 项 | 选择 |
| --- | --- |
| 范围 | B：焦点面优先；其余壳层轻量配色与动效对齐 |
| 气质 | 深空指挥台（近黑、冷青/电蓝、细线仪表） |
| 主题 | A：保留多主题；默认深色增强，其它主题跟 accent 变量 |
| 动效档位 | 2：有仪式（短过场，不挡高频操作） |
| 实现路径 | 方案 2：焦点仪式层（非纯皮肤、非独立 Overlay 引擎） |
| 交互基调 | 每个操作像科幻片机械确认：短、准、有状态，不做长全屏过场 |

## 3. 视觉语言与 Token

### 3.1 色

- `--bg` / `--bg-panel` / `--bg-side`：近黑石墨分层，避免单一死黑。
- `--accent`：电蓝偏青（约 `#4CC9F0` 一带），用于就绪、焦点、AI 活动。
- `--ok` / `--warn` / `--danger`：保留语义，微调饱和度以配冷色舱。
- 边框：低对比细线；关键面 `1px` accent 微光，禁止厚重霓虹辉光与紫色赛博默认脸。

### 3.2 字体

- 界面正文：保留现有中文 UI 字体栈（可读优先）。
- 仪式文案 / 状态码（如 `HANDSHAKE`、`LINK UP`、`EXEC`）：等宽或半等宽，呈现任务日志感。
- 终端本体：仍由用户主题字体控制，不硬改 xterm 阅读体验。

### 3.3 线与面

- 偏直角、小圆角（约 4–6px），仪器面板感。
- 侧栏 / 标签 / 状态栏：细分隔线 + 极淡静态或极慢呼吸纹理，不抢终端内容。

### 3.4 动效节奏

- 连接：300–600ms 短序列（握手脉冲 → 就绪一闪）。
- AI/CLI 卡片：执行中细进度/呼吸；完成轻确认读数。
- 壳层控件：按下 1–2px 下沉 + 边线亮起；悬停细扫描高亮。
- `prefers-reduced-motion: reduce`：全部降为瞬时状态切换，无长动画。

## 4. 交互面设计

### 4.1 连接建立（最高仪式）

触发：用户打开连接，会话进入 `connecting` → `ready` / 失败。

行为：

1. 标签状态点进入机械握手：灰脉冲 → 细扫线 → 电青点亮。
2. 状态栏短文案：`HANDSHAKE` → `LINK UP`（失败为明确错误态）。
3. 就绪时侧栏项与标签细边框闪一次（闸门锁死感）。
4. 失败：红点咬合 + 可选极短微抖（受 reduced-motion 约束）。

约束：不挡终端输入流；不弹全屏过场。

### 4.2 AI / CLI 命令反馈（作战日志）

数据源：既有 AI 面板消息流 + CLI 经 `cli-server` → `cli-trace` 写入的轨迹（`intent` / `say` / op / 输出）。

卡片语言（内置 Agent 与 CLI 共用）：

- 顶栏等宽标签：`EXEC` / `LS` / `MONITOR` / `UPLOAD` 等。
- `--say`（或等价说明）作为本步意图句。
- `--intent`：同一任务内只在意图变化时出现一次用户原话抬头。
- 执行中：卡片左侧细进度条（液压行程感）。
- 完成后：状态码与耗时以机械读数呈现；输出保持可折叠审计形态。

目标：用户能一眼看出外部 agent 正在动哪台机器、在做什么。

### 4.3 日常壳层（轻量对齐）

覆盖：标题栏按钮、侧栏节点、标签切换、弹层开关、状态栏 HUD。

- 按下咬合、悬停细线高亮。
- Modal：短位移舱门滑入 + 遮罩压暗；关闭反向。
- 状态栏：主机/状态等宽小字；关键变更微闪。

### 4.4 明确不做

- 全屏赛博过场、持续吵扫描线背景。
- 紫色霓虹默认美学、厚多层 glow。
- 打断打字或拖慢输入的长动画。
- 重写 SSH/SFTP/CLI 协议或凭据模型。

## 5. 架构与数据流

```
[外部 Agent / Cursor]
        | node skills/liteshell/bin/liteshell-cli.mjs
        v
[cli-server 主进程] --trace--> [渲染进程 AI 面板]
        |                         ^
        +-- SSH/SFTP 会话 --------+ 标签页可见

[用户 UI 操作]
        | IPC
        v
[main: ssh / agent] --> 会话状态 / Agent 消息 --> 同一套卡片与状态点仪式
```

- CLI 同步是既有能力验收，本规格不新增协议。
- UI 层消费状态与轨迹事件，用 CSS/少量 DOM 类名驱动仪式；尽量少改 `cli-trace` 文案逻辑。

## 6. 文件改动范围

| 区域 | 预期 |
| --- | --- |
| `src/renderer/src/style.css` | 指挥台 token、壳层咬合、边线与 HUD |
| `src/renderer/src/animations.css` | 连接序列、卡片进度、舱门、reduced-motion |
| `src/renderer/src/main.ts`（及 agent 渲染相关） | 连接状态类名钩子；任务卡结构（标签/进度/读数） |
| `src/renderer/index.html` | 仅在必要时增加仪式挂点 class，不改信息架构 |
| `src/main/cli-trace.ts` / `cli-server.ts` | 默认不改；仅当面板缺字段时做最小消费侧补齐 |

不改：SSH 协议栈、凭据存储、xterm 核心、CLI socket 契约（除非验收证明缺字段）。

## 7. 错误处理与降级

| 情况 | 行为 |
| --- | --- |
| 连接失败 / host key 变化 | 错误态机械反馈；文案仍走现有日志/提示 |
| CLI `app_not_running` | 验收时记为环境问题，提示先打开 LiteShell |
| `prefers-reduced-motion` | 无序列动画，仅最终状态色/文案 |
| 主题切换 | 不破版；硬编码色禁止，走变量 |

## 8. 测试计划

### 8.1 UI

1. 连接成功：可见 handshake → link up；侧栏/标签闸门闪。
2. 连接失败：红态咬合，无卡死动画。
3. 壳层：按钮/标签/侧栏/弹层有按下与细线反馈。
4. 主题切换与 reduced-motion 抽检。
5. `npm run typecheck`；必要时相关前端冒烟。

### 8.2 CLI 同步（技能包）

前提：LiteShell 进程在跑（可托盘），至少一条可用连接。

```powershell
$CLI = "$HOME\.claude\skills\liteshell\bin\liteshell-cli.mjs"
# 若未安装技能包，改用仓库内：
# $CLI = "e:\my-project\liteshell\skills\liteshell\bin\liteshell-cli.mjs"
node $CLI conns
node $CLI exec <连接名> "uname -a" --intent "看看这台机器是什么系统" --say "读取内核与主机信息"
```

期望：

1. AI 面板出现 intent 抬头（任务切换时一次）。
2. 出现带 `EXEC` 标签与 `--say` 的任务卡，执行中有进度，完成后有输出/读数。
3. 终端/标签侧能看到会话被驱动（按现有复用行为）。
4. 可选：`monitor` / `ls` 各测一条，确认标签名映射正确。

回归：`npm run test:cli-trace`、`npm run test:skill`（若环境具备）。

## 9. 非目标（本轮）

- 音效（若后续需要另开规格）。
- 亮色主题的完整指挥台重做（仅变量跟随）。

# 安全模型与已知取舍

[返回 README](../README.md)

## 凭据怎么存

- **密码、API Key、私钥口令**经系统钥匙串（Windows DPAPI / macOS Keychain / Linux libsecret）加密后
  写进 `liteshell.json`。系统没有可用钥匙串时，退回同目录的 `vault.key`（0600）做 AES-256-GCM。
- **IPC 边界上只传密文**：SSH 密码、API Key、私钥口令在渲染进程里只以 `hasSecret` 这样的布尔标记出现。
  唯一的例外是**内嵌远程桌面的 RDP 密码**——CredSSP 要在那个窗口的 WASM 客户端里完成，它必须被
  交付一次，见下面的「已知取舍」。它不落盘、不进日志，窗口关闭即丢弃。
- **主机密钥 TOFU**：首次连接记录指纹，之后变化直接拒绝并提示，防中间人。
- **导入/导出备份**：密码和私钥口令只有在你给导出设了口令时才跟着走，那时用 scrypt(32 MB) +
  AES-256-GCM 加密；不设口令就留在本机钥匙串里，别的机器解不开。口令错误或文件被改动会整体拒绝导入。
- **终端背景图片**：只保存文件路径，图片留在你选的那个位置，不会被复制进应用数据目录。
  显示时由主进程读成 data URL 交给渲染层，所以页面不需要 `file://` 读盘权限（CSP 的 `img-src`
  依旧只有 `self` 和 `data:`）。图片是本地文件，本身没有敏感信息——但路径会写进
  `liteshell.json`，备份时会跟着走。

## 已知取舍

- **导出包里私钥是明文**（base64 的 PEM，和 FinalShell 自己的 `config.json` 一样）。
  文件按 0600 写，但既然是明文，传出去就得自己负责。
- **私钥库里的密钥是明文文件**，放在 `<用户数据目录>/keys/`（0600），和 FinalShell 的做法一致。
  密钥本身的口令存在钥匙串里、连接时交给 ssh2 解密，但 LiteShell 不会把密钥文件重新加密。
- **「配置本机免密登录」会改动你的 `~/.ssh`**：生成一把**没有口令**的私钥
  `~/.ssh/liteshell_ed25519`，把公钥追加到服务器的 `authorized_keys`，并在 `~/.ssh/config`
  顶部写一段带标记的 Host 块。无口令是让 `ssh IP` 不用再输入；拿到这个文件就等于拿到该服务器账号，
  请按密码对待。只加公钥、不改服务器上已有的条目；同一主机的 LiteShell 块会被替换。
- 依赖 `nvidia-smi` 看显存；没有 NVIDIA 卡就只显示 CPU / 内存 / 磁盘
- 终端编码固定 UTF-8（FinalShell 的连接配置里也全是 UTF-8）
- 暂无通用端口转发 / ProxyJump / 跳板机链路；远程桌面用的是一条**只为一次 RDP 会话存在**的临时链路
- **远程桌面隧道**只监听 `127.0.0.1` 的随机端口，不把 3389 暴露到局域网；临时 `.rdp` 文件里只有地址和
  用户名，客户端退出即删除。系统客户端模式下 RDP 密码由外部客户端询问，LiteShell 不保存、不经过 IPC。
  首次连接的 RDP 证书名不匹配（连的是 `127.0.0.1`）属于预期：主机身份由 SSH 主机密钥保证
- **内嵌远程桌面**的 RDP 密码必须交给渲染进程，因为 CredSSP 在 WASM 客户端里完成。它只在
  `desktopAttach` 的返回值里出现一次，留在主进程内存与该窗口内，不写盘、不进日志，窗口关闭即丢弃；
  SSH 密码仍然只在主进程里。RDCleanPath 代理只监听回环地址，URL 路径和请求体里各带同一枚随机 token，
  没有 token 的连接会被拒绝。代理替浏览器终止 TLS，证书指纹写入日志，信任根仍是 SSH 主机密钥。
  CSP 只为内联的 IronRDP WASM 放开了 `wasm-unsafe-eval` 和 `connect-src data:`，没有放开 `unsafe-eval`
- 暂无 X11 转发、ZMODEM 传输
- 应用图标是 `scripts/make-icon.mjs` 用距离场画出来的（`npm run icon`，无图形库依赖），
  要换成正式设计稿直接覆盖 `build/icon.png`（512×512 起，`.ico` / `.icns` 由 electron-builder 现生成）
- **AI 助手会把服务器上的东西发给你配的那个模型**：只读工具返回的文件内容、命令输出都在里面。
  介意就别让它 `cat` 敏感文件——闸门管的是「会不会改坏」，不是「能不能外传」。
- AI 的写闸门是**绊线不是边界**：`src/main/gate.ts` 是纯正则分类器，判不准的一律按危险算，
  但它拦不住 `awk 'BEGIN{system("…")}'` 这种把命令藏在参数里的写法。真正的边界是你点的那一下。
- 只读工具自动跑，只读的 `exec` 命令也自动跑（见 [功能详解](features.md#ai-助手)），其余每条都要点一下。
  **没有「本次全自动」这一档**，也还没有按主机记的信任范围——等真实使用里的打扰频率有数了再说
- AI 的 `upload` / `download` 会动文件，而且跨了本机/远端这条边界：**上传会覆盖远端同名文件，
  下载会写进本机「下载/liteshell」**。两个方向都每次都问，闸门按工具名判，不看路径文本。
  模型只能传你亲口给过的本机路径；下载的落地目录固定，不让它挑地方
- AI 能新建/修改本机连接（`save_connection` / `save_folder`），但**密码永远不经过模型**：
  `list_connections` 只回 `hasSecret` 真假而从不回密文；`save_connection` 的参数表里没有密码字段，
  写出来的是一条等你点开补密码的空壳连接。两条都每次都弹卡片（闸门按工具名判，与命令文本无关），
  而它们只改这台客户端上的 `liteshell.json`，不碰服务器
